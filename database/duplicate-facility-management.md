# 중복 시설 관리와 공공데이터 변경 검토

2026-09-17 · 운영 반영 완료 · [중복 관리 인수](https://github.com/toilet-project/docs/issues/109) · [변경 검토 인수](https://github.com/toilet-project/docs/issues/99)

## 같은 이름은 중복의 증거가 아닙니다

관리자는 **그룹 목록 → 시설 목록 → 지도·시설 정보**의 3열 화면에서 판단합니다. 같은 좌표·같은 지역구 필터로 범위를 좁히고, 전체 지도에서 목록과 같은 순번 마커를 비교합니다. 좌표가 없으면 목록·시설 정보는 남기고 임의 위치를 만들지 않습니다.

## 두 가지 숨김

| 구분 | 시설 숨김 | 작업 목록 숨김 |
| --- | --- | --- |
| 목적 | 실제 중복의 대표 시설만 사용자에게 제공 | 검토할 필요가 없는 이름 그룹을 개인 작업 목록에서 제외 |
| 영향 | 공개 목록·상세·사이트맵·관리자 기본 시설 목록에서 제외 | 해당 관리자 목록만 변경 |
| 선택 | 대표 시설 + 숨길 시설 + 판단 근거 | 그룹 행 스위치 |
| 보존 | 원본·리뷰·제보, 당시 이름·주소·좌표·근거·변경 이력 | 관리자별 설정 |
| 되돌리기 | 명시적 숨김 해제 | 숨김 포함 조회 후 스위치 해제 |

대표 지정은 자동 병합이 아닙니다. 숨긴 시설의 공개 상세 API는 404이며 신규 리뷰 접수는 차단합니다. 중복 이름·중복 좌표 두 화면에서 동일한 시설 숨김 기능을 사용합니다.

## 공공데이터가 달라졌을 때

1. 배치가 원천 데이터를 수신합니다. 관리자 확정 좌표·주소는 바로 덮어쓰지 않습니다.
2. 다른 값은 변경 후보와 수신 증빙으로 보관합니다. 숨김 시설의 이름·주소·좌표 변경은 당시 숨김 이력과 연결합니다.
3. 관리자는 현재 값과 제안 값, 위치 차이, 수신 시각, 숨김 근거를 비교합니다.
4. **변경 반영 / 현재 값 유지 / 나중에 검토** 중 선택합니다. 오래된 버전의 결정·동시 수정은 거부합니다.
5. 반영 시 이력·관련 지역 재판정·캐시 갱신을 연결합니다. **변경을 반영해도 숨김은 자동 해제하지 않습니다.**

일반 공개 시설의 모든 필드를 승인제로 바꾼 것은 아닙니다. 보호 대상과 다른 원천 필드의 기존 동기화 정책은 구분합니다.

## 검증 범위

- 시험 DB·CI: 마이그레이션, 권한·기능 OFF, 동시 변경 409, 이력 단일 생성, 공개 제외·복원, 캐시 이벤트, 변경 후보 연결.
- 운영: 배포 상태·스키마·기존 트리거 보존, 인증된 목록·필터·전체 지도, 기존 통계·회원·리뷰 기능 보존.
- 운영 시설을 시험 목적으로 숨기거나 수정하지 않았습니다. 실제 공공데이터 자연 변경은 [10월 점검](https://github.com/toilet-project/docs/issues/95)과 구분합니다.

“서로 다른 시설로 검토 완료 → 정보 변경 시 작업 목록에 자동 복귀”는 아직 구현하지 않았습니다. 현재 관리자별 HIDE는 수동 설정입니다.
