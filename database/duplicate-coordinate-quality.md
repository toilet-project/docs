# 중복 좌표 데이터 품질 관리 v1.0

> 기준일: 2026-08-31 · 대상: 공공데이터 지오코딩 결과와 관리자 확정 좌표

## 목적

공공데이터의 주소가 동일해 여러 화장실이 같은 좌표로 지오코딩된 경우를 운영자가 검색·검토하고, 사용자 위치 제보 또는 관리자 확인을 통해 점진적으로 품질을 높인다.

## 운영 원칙

- 이름이나 층수만으로 실제 좌표를 자동 추정하지 않는다.
- 동일 좌표는 사용자 지도에서 목록으로 모두 제공하며, 관리자 화면에서는 그룹 단위로 관리한다.
- 그룹 상태는 `PENDING`, `NEEDS_CORRECTION`, `CONFIRMED_SHARED` 중 하나다.
- 개별 화장실의 좌표는 사용자 위치 제보 승인 또는 관리자 직접 확인으로만 변경한다.
- 좌표 변경 전·후 값, 도로명 주소, 수행 관리자, 적용 시각과 경로를 `coordinate_revision`에 남긴다.
- 확정된 좌표는 `toilet.coordinate_source=ADMIN_CONFIRMED`로 바꿔 배치 지오코딩이 덮어쓰지 못하게 한다.

## 데이터 흐름

1. API가 `toilet.latitude, longitude`를 그룹화해 2건 이상인 좌표만 페이지 단위로 집계한다.
2. 운영자는 화장실명·주소·관리번호, 확인 상태로 그룹을 검색한다.
3. 상세에서 그룹의 모든 화장실, 대기 위치 제보, 과거 수정 이력을 확인한다.
4. 실제 공동 위치라면 그룹만 확인 완료 처리한다.
5. 잘못된 좌표라면 기존 위치 제보를 검토하거나 카카오맵에서 개별 화장실 위치를 보정한다.
6. 직접 보정은 `ADMIN_DIRECT`, 제보 승인은 `USER_REPORT_APPROVED` 이력으로 구분한다.

## DDL 변경

Flyway V5는 `coordinate_quality_review`를 생성하고, 사용자 제보 없이 수행한 관리자 보정도 같은 이력 테이블에 기록할 수 있도록 `coordinate_revision.report_id`를 nullable로 변경한다. 운영 DB에 문서 SQL을 직접 재실행하지 않는다.

## 검증 기준

- 목록 건수와 상세 화장실 수가 동일 좌표 집계 결과와 일치한다.
- 다른 좌표로 이동한 화장실은 기존 그룹 상세에서 제외된다.
- 직접 보정 후 `coordinate_source`가 `ADMIN_CONFIRMED`이고 이력·감사 로그가 모두 남는다.
- 위치 제보가 있는 그룹은 제보 검토 화면으로 연결된다.
