# 회원 복구·파기 배포 안전장치 보완

2026-09-07 KST. **feature 코드 보완 및 로컬 검사 통과 / 운영 미적용**.

[9월 6일 사전 검토](account-erasure-production-readiness-2026-09-06.md)에서 발견한 환경 전달·중지 경로 누락을 보완했다. 기존 보고서는 당시 기록으로 보존한다.

## Redis가 필요한 이유

새 Redis를 추가하는 작업이 아니다. 기존 API의 로그인 유지용 리프레시 토큰 정보와 10분짜리 계정 복구 인증 정보가 Redis에 있으므로, 회원 파기 시 배치도 같은 Redis에서 해당 회원의 인증 정보만 제거해야 한다. MySQL의 계정 상태/auth_version 검사도 함께 적용한다. Redis 정리가 실패하면 SQL 파기를 완료하지 않고 재시도한다.

| 저장소 | 담당 정보 |
| --- | --- |
| MySQL | 회원·탈퇴 선택 동의·3개월 기한·재시도 상태 |
| 기존 Redis | 로그인 유지·계정 복구 인증 정보와 회원별 키 목록 |
| R2 | 백업 복원 후 삭제 계정이 되살아나는 것을 막는 암호화 파기 대장 |

배치는 API와 같은 Redis 호스트·포트·DB·비밀번호를 사용해야 한다. 전체 Redis 키 삭제나 비밀번호 변경은 필요하지 않다.

## 변경한 안전장치

- API에 `AccountLifecycleGate`를 추가했다. `ACCOUNT_LIFECYCLE_MAINTENANCE=true`가 탈퇴·복구 조회/확인·탈퇴 계정 OAuth 후속 처리·직접 파기 서비스까지 차단한다. 복구 취소는 인증 증명을 지우는 동작이라 허용한다.
- 유지보수 OFF에서는 `ACCOUNT_RETENTION_ENABLED`가 복구를, `ACCOUNT_ERASURE_ENABLED`가 실제 파기를 제어한다. 신규 탈퇴 접수는 두 기능이 모두 켜져야 허용한다.
- 배치도 같은 maintenance 설정으로 정기 후속 작업과 직접 worker 파기를 이중 차단한다. 기본값은 maintenance true, 기능 false다.
- 이 플래그는 프로세스 시작 시 읽는다. DB 분산 잠금이나 실시간 중지 버튼이 아니며, 운영에서 변경할 때 모든 관련 API/배치 프로세스를 drain/restart하고 확인해야 한다. 이미 진행 중인 트랜잭션을 즉시 취소한다고 보장하지 않는다.
- 배포 전 `ACCOUNT_LIFECYCLE_DEPLOYMENT_APPROVED=true`가 없으면 이미지 push·운영 SSH 전에 중단한다. 이번에는 해당 운영 승인 변수를 설정하지 않는다.
- 현재 workflow는 준비 배포만 허용하며 maintenance true, retention/erasure/ledger/catalogue false를 고정한다. 활성화는 별도 검토 변경이 필요하다.
- R2 설정/시크릿 전달을 구현했다. JSON·특수 문자는 쉘에서 재해석하지 않고 마스킹된 base64로 전달하여 0600의 별도 Compose env 파일에 보관한다. base64는 암호화가 아니며 이 파일은 비공개 운영 설정이다.
- API의 Redis 컨테이너에는 새 R2 자격 증명 파일을 주입하지 않는다. 배치는 별도 Redis를 만들지 않는다.
- API의 기존 Redis 비밀번호 누락은 사전 검사에서 차단한다. 비활성 배치 준비 모드의 누락은 `redisConfigured=false`로 구분하며 연결 완료로 보지 않는다.
- V11 SQL은 수정하지 않았다. 현재 Flyway 단일 적용 경로를 명시하고 수동 중복 DDL/이력 조작을 금지했다.

## 로컬 검사

- API 선택 회귀: **59건 통과**, 실패/오류/건너뜀 0.
- 배치 전체 회귀: **163건 중 159 통과·4 건너뜀**, 실패/오류 0.
- Node 배포 구성 검사: API·배치 각각 4건 통과. 승인/중지 플래그 강제, 비활성 준비 상태, JSON/Redis 특수문자 전달, 잘못된 키·endpoint·줄바꿈/따옴표 거부.
- 공유 파기 Java 계약 8개 동일. 기존 실제 백업 MySQL 검증의 SQL은 변경하지 않았다.
- 신규 Java 검사에는 점검 모드 복구 진입 차단, 직접 서비스의 DB/대장 접근 전 차단, 탈퇴 계정 OAuth 차단, 배치 직접 호출 차단을 포함한다.

실제 Redis/R2 왕복, 실제 OAuth·운영 MySQL migration은 이번 로컬 검사에 포함하지 않았다. 현재 비밀번호를 새로 만들거나 운영 DB·타이머·파기 기능을 변경하지 않았다.

## 남은 운영 조건

1. 배치 저장소 `REDIS_PASSWORD` 등록은 사용자 승인 후 완료했다(2026-09-07 00:11 KST). 미니 PC API 설정과 현재 API 컨테이너 값의 일치를 확인한 뒤 메모리 파이프로 복사했고 값/파일을 공개하지 않았다. 서버 비밀번호는 변경하지 않았다. GitHub 등록과 실제 배치 Redis 연결은 다르므로 운영 연결 검증은 아직 남아 있다.
2. R2 endpoint 등 운영 변수·키 유효성, 실제 대장/독립 기준·DB 복원 세대·백업/키 복구 확인.
3. 웹/정책 전환과 점검 시간을 승인받는다. 준비 배포도 기존 탈퇴가 점검 상태로 바뀌므로 무영향 배포가 아니다.
4. feature PR 및 Linux CI 검토 후 main 병합·V11/운영 배포를 별도 승인한다. 기능 활성화 승인은 그 이후다.

이번 코드 보완이 운영 연결 완료나 개인정보 수명주기 전체 완료를 뜻하지 않는다.
