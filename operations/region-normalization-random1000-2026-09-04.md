## 목적과 안전 범위

현재 정규화 규칙으로 자동 저장 가능한 행정구역 파생 데이터와 추가 검증/수동 확인 대상을 구분한다. `VERIFIED`는 시도·시군구 수준 주소 교차검증 성공을 뜻하며, 정확한 출입구 위치 또는 같은 시군구 내 잘못된 좌표가 없음을 보증하지 않는다.

기존 화장실 주소·좌표, 관리자 확정 값, 운영 DB 스키마를 수정하지 않는다. 이번에는 기능 코드 수정·배포·전수 적용도 하지 않는다. 주소가 틀렸다고 가정해 다시 지오코딩한 좌표로 교체하지 않는다.

## 표본 선정

- 전체 53,576건 중 위도와 경도가 모두 있는 52,288건이 모집단이다.
- 좌표 없는 1,288건은 이번 표본 추정 범위 밖이며 별도 fallback 검증 대상이다.
- 무작위 seed와 화장실 ID의 SHA-256 정렬에서 첫 1,000개를 비복원 추출했다. ID순 상위 1,000건이나 앞선 의도 표본 84건을 재사용한 것이 아니다.
- 표본에는 서로 다른 좌표 987쌍이 있다. 같은 좌표 응답은 캐시하되, 주소별 판정은 화장실 행마다 실행한다.
- 선정 후 처리 순서만 ID순으로 바꿨다. 중간 진행률은 지역 편향이 있으므로 최종 1,000건 전에 전국 비율로 환산하지 않는다.
- 이번 표본의 좌표 출처는 모두 `GEOCODED_LEGACY`다. 드문 관리자 확정 사례의 정확도를 이 표본으로 별도 추정하지 않는다.
- 선정 seed: `f32353ff6f3c06f1520630149fbc02bf`. 도로명·지번 모두 있음 641건, 도로명만 273건, 지번만 86건, 둘 다 없음 0건이다.

## 실행 보호

- 기존 검증 jar 재사용: SHA-256 `ce7d0e0bf4c300db47889d9c52512c9b2450697e287d9b8555de18a0bf94df42`.
- 100건씩 10회 dry-run, 공유 journal로 좌표 캐시·checkpoint·호출 수를 유지한다.
- 기본 분석 초당 최대 1회, 호출 예산 1,200회, heap 256MiB, CPU 인식 1개, 낮은 실행 우선순위.
- HTTP 401/403/429는 중단한다. 기존 도구의 일시적 네트워크/5xx 재시도는 최대 3회 시도다.
- 표본 SQL은 READ ONLY 트랜잭션에서 SELECT만 수행한다. Java CLI는 `--apply`/`--fill-missing` 없이 실행하며 Spring/Flyway/정기 배치를 시작하지 않는다.
- 종료 후 선정 시 스냅샷과 현재 DB 주소·좌표·좌표 출처를 다시 비교한다.

## 추가 진단 방법

기본 판정이 VERIFIED가 아닌 표본만 별도로 `coord2address`와 기존 주소 검색 API에 대조한다. 원래 판정 journal을 수정하지 않고 새 근거를 따로 남긴다. 추가 주소 검색은 후보가 정확히 1건일 때만 기존 좌표와 거리를 비교한다. 둘 이상의 후보는 첫 결과를 골라 정상 처리하지 않는다.

추가 진단은 기본 분석 종료 후 순차 실행하며 초당 최대 1회, 자체 400회 및 기본 분석 포함 합계 1,500회 중 먼저 도달한 한도에서 중단한다. 앱 전체 공유 잔여 쿼터를 의미하지 않는다. 추가 진단의 HTTP 401/403/429는 즉시 중단, 그 외 실패도 목록에 남긴다.

50m 이내·시군구 코드 일치는 자동 재검증 규칙을 검토하기 위한 보조 기준일 뿐 자동 좌표 변경 허용치가 아니다. 출입구 단위 정확성은 보증할 수 없으며 지역 경계나 공급자 코드 불일치는 계속 보류한다.
