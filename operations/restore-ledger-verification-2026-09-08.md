# 실제 파기 대장·격리 복원 검증 결과

**기준 시각: 2026-09-08 21:03 KST.** 준비 배포, 일회성 격리 시험, 정기 점검 설치를 구분하여 기록한다.
회원별 데이터·비밀값·내부 주소·서버 파일 경로는 공개하지 않는다.

## 결론

실제 R2 파기 대장과 독립 체크포인트를 정기 격리 복원에 연결하고, 설치된 정기 실행 환경에서
수동 1회 성공을 확인했다. **실제 대장은 0건**이다. 실제 회원이 있는 대장의 재삭제 실적이나
탈퇴·계정 복구·자동 파기 기능 활성화까지 완료했다는 뜻은 아니다.

## 일회성 가상 계정 시험의 검증 범위

- 소셜 계정·동의·알림·역할·탈퇴 정보 정리 및 제보·좌표·감사 이력의 개인 참조 제거.
- 비대상 회원, 제보·좌표 내용 보존.
- 회원 생성 시점 불일치 시 일부 삭제 없이 중단.
- 예상하지 못한 외래키가 있을 때 전체 트랜잭션 롤백.
- 같은 기록을 반복 적용해 추가 삭제 0건임을 확인.
- 가상 데이터 제거 후 기존 데이터의 전체 행 지문이 같음을 확인. 지문과 회원 행은 공개하지 않음.

이 시험의 94개 조건과 정기 검증기의 37개·9개 자동 검사는 서로 다른 범위다. 하나의 동일한
전체 테스트 수로 합산하지 않는다. 상세 [정기 검증 흐름과 실패 기준](restore-ledger-gate.md)을 참고한다.

## 설치 후 확인

- 실제 대장 0건과 독립 체크포인트 시퀀스 1 일치.
- 복원 → 대장 dry-run → 격리 DB 적용 → 재적용 → 외래키 확인 → 대장 재대조 → 임시 자원 정리 통과.
- 보호 백업 해시는 이미 최신이어서 `ALREADY_CURRENT`. 새 검증 영수증만 추가했다.
- 설치 스크립트·클래스 해시 재확인, 실패 표식 없음, 검사 컨테이너·네트워크 잔여 없음.
- 성공한 시험의 임시 설정 사본만 제거. 원본 설정·암호화 백업·옛 Redis 파일은 보존.
- 기존 실패 알림 연결 유지. 장애 주입이나 추가 테스트 알림 전송은 하지 않았다.
- `productionDatabaseModified=false`, `retentionEligible=false`. 운영 R2·독립 GitHub에 쓰지 않았다.

이 기록으로 상위 WBS 전체를 닫거나 과거 사본 삭제를 승인하지 않는다.
