## DB·기존 구현·역지오코딩

원본 toilet PK는 toilet_id, 주소는 road_address/jibun_address 문자열, 좌표는 latitude/longitude DECIMAL(10,7)이며 coordinate_source를 별도로 관리한다. 9/5 운영 조회에서 Flyway baseline 0 및 V1~V7 성공 상태, 신규 region 테이블/view는 없었다. 상세 스키마와 등록·수정 경로는 [기존 구현 보고서](region-normalization-review-2026-09-04.md)에 있다.

기존 Kakao 주소 검색을 재사용한다. 공공데이터 최초 좌표 생성의 첫 번째 검색 결과 정책은 유지한다. 행정구역은 실제 좌표의 coord2regioncode B(법정동) 응답으로 판별하고 H(행정동) 코드는 따로 보관한다. 주소 문자열은 보조 검증이며 유일한 결정 기준이 아니다. 불확실 건은 coord2address 및 구조화된 주소 검색 결과가 단일 결과·코드 일치·기존 좌표와 50m 이내일 때 추가 통과시킨다.

동일 좌표는 역지오코딩 캐시를 재사용한다. 최초 대상 52,288건의 서로 다른 좌표는 42,643개였다. 추가 검증·재시도 때문에 API 호출 수와 화장실 처리 건수는 다르다.

## 최종 설계·컬럼·인덱스

원본을 보존하는 1:1 파생 테이블 toilet_region 및 판정 이력 toilet_region_assessment_history를 사용한다. region master/slug는 만들지 않는다. 시도 이름/2자리 코드, 시군구 이름/5자리 코드, 원래 법정동/행정동 10자리 코드를 각각 저장한다.

시→구는 city_name/district_name으로 보존하여 수원시→영통구, 천안시→서북구 조회가 가능하다. 부모 시 코드를 추측하지 않는다. 세종은 제공된 시도/코드로 처리하며 없는 하위 이름을 만들지 않는다. current_toilet_region은 VERIFIED이고 현재 원본 주소/좌표와 판정이 일치할 때만 조회한다.

V8에는 시도, 시군구, 시도+시 이름 조회 인덱스, V10에는 상태별 검토 목록·화장실별 이력·중복 재생 방지 유일키가 있다. 이번 후속 작업에서 신규 DDL/인덱스 변경은 없다. V9는 별도 목적의 제보/좌표 확정 도로명·지번 저장 분리다. 컬럼별 한글 설명과 DDL은 [v1.8](../database/administrative-region-normalization-v1.8.md), [v1.9](../database/coordinate-address-fields-v1.9.md), [v1.10](../database/region-assessment-history-v1.10.md)을 참고한다.

## 반영 방식·자동 갱신

새 RegionReplayCli/RegionReplayJob은 JSONL과 SHA256을 검증하고 외부 HTTP provider나 API 키 없이 결과만 재사용한다. 손상 파일은 DB 연결 전에 실패한다. 현재 DB를 100건씩 읽어 원본 지문·버전·TTL을 비교하며 변경/누락/만료/잘못된 결과를 ID별로 보고한다.

기본 dry-run은 SELECT만 수행한다. 명시적 --apply에서만 행 잠금·원본 재확인 후 파생 정보와 이력을 같은 트랜잭션에 저장한다. 이미 같거나 최신인 판정은 skip한다. 좌표 채움 옵션은 제공하지 않는다. [실제 반영 순서·백업·롤백](region-production-apply-plan-2026-09-05.md)을 따른다.

운영 읽기 전용 전수 모의 실행: 스캔 53,582 / 적용 후보 52,294 / 현재 소스 불일치 0 / 잘못된 결과 0 / 입력 없는 좌표 보유 항목 0 / API 0 / DB 적용 0. 원본 전후 변경·삭제 0. 실제 apply 시에도 다시 확인한다.

정규화 워커는 기본 OFF다. 활성화 후 실제 좌표/주소 변경을 지문으로 감지한다. 관리자가 좌표를 확정하면 이전 파생 결과는 view에서 즉시 제외되고 워커가 새 판정을 만든다. 주소 오타 수정은 좌표를 바꾸지 않고 교차검증만 갱신한다.

이번 검토에서 fillMissing=false여도 주소 후보 검색을 하던 경로를 보완했다. 이제 좌표 누락은 ADMIN_COORDINATE_REQUIRED, 부분 좌표는 PARTIAL_COORDINATE로 남기며 외부 검색을 하지 않는다. 관리자 입력 후 지문 변경으로 정규화한다.

## 호출 제한·재시도

실시간 정규화는 초당 1회, 호출 전 예산 기록, 네트워크/5xx 제한 재시도, 401/403/429 중단, 좌표 캐시 및 파일 체크포인트를 사용한다. 전수+후속 46,831회는 승인된 50,000회 이내다. 반영 전용 실행은 API 0회다. 운영 워커의 일일 예산과 영속 journal 경로는 배포 시 확정한다.

1. 사용자 코드 검토와 batch main/배포 승인, 운영 백업·격리 복구 확인.
