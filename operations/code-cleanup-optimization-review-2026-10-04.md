# 급똥 코드 정리·최적화 검토 · 2026-10-04

웹·API·관리자·배치의 최신 기본 브랜치와 현재 모바일 구현을 검토했다. 호출되지 않는 작은 코드는 정리 PR을 준비했고, 더 큰 개선은 **의존성 업데이트 → 관리자 분석 조회 → 웹 지도 화면 분리 → 내 제보 페이지 처리** 순서로 진행하는 것을 권장한다.

현재 단계는 코드 검토와 1차 정리다. 정리 PR은 자동 검증을 통과했으며 아직 병합·운영 반영하지 않았다. 실제 사용 환경의 속도·DB 부하를 측정하지 않았으므로 성능 개선 수치를 주장하지 않는다.

## 검토 범위와 방법

웹·API·관리자·배치·문서·운영 체크포인트는 최신 `main`을 별도 작업 공간에서 확인했다. 기존 개발 폴더의 미커밋 변경은 보존했다. 모바일은 버전 0.1.53의 로컬 소스이며 독립 Git 저장소가 없어 수정하지 않았다. 진행 중인 웹 게임도 검토에 포함하되 운영 기능으로 간주하지 않았다.

진입점·호출 참조·테스트·배포 및 운영 스크립트를 함께 확인했다. TypeScript import/export 분석은 삭제 후보를 찾는 보조 수단으로만 사용했다. 프레임워크 자동 진입점, 플랫폼별 파일, 테스트 전용 코드와 수동 복구 도구는 참조가 적다는 이유만으로 삭제하지 않았다.

| --- | --- | --- |

모든 화면의 실사용 시나리오를 수동으로 다시 실행한 것은 아니다. 특히 실제 로그인·광고·iOS/Android 기기 성능·운영 DB 실행 계획은 후속 검증 범위다.

### 의존성 업데이트의 적용 범위

검토 시 웹의 Next.js는 16.3.4이며 [기존 업데이트 PR #345](https://github.com/toilet-project/toilet-web/pull/345)은 16.3.6으로 올린다. 기존 Workers 검증은 설치 단계의 새 패키지 출시 후 대기 정책에서 중단됐다. 이는 코드 테스트 실패와 구분하며, 대기 정책을 해제하는 방식으로 처리하지 않는다. 최신 기본 브랜치와 다시 검증해야 한다.

[Next.js 공식 보안 공지](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j)는 Node.js `ImageResponse`에서 공격자가 제어하는 SVG 입력을 처리하는 경로를 설명한다. 검토한 서비스 소스에는 `next/og`·`ImageResponse` 사용처가 없었다. 따라서 이번 정적 검토만으로 현재 서비스가 그 공격 경로에 노출됐다고 단정하지 않는다. 그래도 수정 버전 반영은 우선 검토한다.

`undici`와 `brace-expansion`도 업데이트 후보다. 잠금 파일에서 전자는 Miniflare, 후자는 minimatch의 간접 의존성으로 확인했다. 빌드·미리보기 도구와 배포된 Worker에서의 실제 사용을 구분해 상위 패키지 업데이트를 검증해야 한다. Dependabot 경고에는 선언 파일·잠금 파일 및 여러 버전의 중복이 있으므로 경고 개수를 서로 다른 운영 취약점 수로 해석하지 않는다.

### 관리자 상세 분석

[AnalyticsExploreService](https://github.com/toilet-project/toilet-admin-api/blob/main/src/main/java/com/example/toiletadmin/analytics/service/AnalyticsExploreService.java#L29)는 최대 32개 항목의 60초 캐시를 사용한다. 반복 조회 보호는 이미 있지만 캐시 미적중 시 상세 구간의 모든 차원을 조회하며 비교 기간도 같은 과정을 반복한다. [차원별 SQL](https://github.com/toilet-project/toilet-admin-api/blob/main/src/main/java/com/example/toiletadmin/analytics/service/AnalyticsExploreRepository.java#L79)은 원본 이벤트에서 일별 distinct 값을 집계한다.

우선 실제로 연 탭에 필요한 차원을 조회하는 방법을 검토한다. 전체 메서드 잠금은 서로 다른 필터 요청도 직렬화하므로, 필요하면 요청별 중복 방지와 제한된 동시 실행으로 바꾼다. 미니 PC에서 무조건 쿼리를 병렬 실행하면 부하가 늘 수 있다. 일별 추정 방문자 합계·세션·봇 제외·유입 근거의 의미와 원본 보관 기간을 바꾸지 않는 것이 완료 조건이다.

### 웹 지도 화면과 내 제보

[지도 App](https://github.com/toilet-project/toilet-web/blob/main/src/App.tsx)는 초기 지도, 검색, 선택, 로그인, 리뷰·제보·회원 패널 상태를 함께 가진다. MapShell이 App을 지연 로딩하더라도 App 내부에서 여러 패널을 함께 가져오는 구조는 남는다. 책임을 작은 단위로 나누고 드문 패널을 지연 로딩하는 후보이며, 분리 자체를 성능 개선으로 간주하지 않는다. 기존 SDK 생명주기·위치 권한·주소 취소·사용자별 상태 초기화를 보존해야 한다.

[내 제보 서비스](https://github.com/toilet-project/toilet-api/blob/main/src/main/java/com/example/toiletapi/report/service/ToiletReportService.java#L91)는 사용자 이력을 모두 반환한다. 웹과 모바일의 표시 개수 제한만으로 서버 응답 크기는 줄지 않는다. 리뷰·알림에 이미 있는 페이지 처리 방식과 맞추되 기존 앱이 사용하는 응답 형식을 갑자기 바꾸지 않는다.

### 모바일·공통 코드에서 보존할 부분

모바일 `src/map/api.ts`는 현재 로컬 카탈로그를 조회한다. `areaCache.ts`의 `MapAreaCache`·`loadCachedMapArea`·`bufferedMapArea`는 테스트 외 사용처가 없지만, 같은 파일의 `areaCount`와 좌표 범위·마커 완전성 함수는 실제 화면에서 사용한다. 파일 전체 삭제는 부적절하다. 지도 집계의 중심점을 범위로 오해해 개수를 만들어내지 않는 보호 로직도 유지한다.

API·배치의 같은 계정 클래스들은 실제 보존·파기·복구 경로다. 중복을 줄이더라도 동시 배포가 필요한 변경으로 만들지 않도록 버전 계약과 동일성 검증부터 도입한다. 게임 아트 함수도 모바일에서 쓰이지 않는다는 이유만으로 지우면 웹 게임의 공유 원본과 어긋날 수 있다.
