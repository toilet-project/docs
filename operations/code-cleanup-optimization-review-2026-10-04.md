# 급똥 코드 정리·최적화 검토 · 2026-10-04

웹·API·관리자·배치의 최신 기본 브랜치와 현재 모바일 구현을 검토했다. 호출되지 않는 작은 코드는 정리했고, 후속 개선은 **의존성 업데이트 → 관리자 분석 조회 → 웹 지도 화면 분리 → 내 제보 페이지 처리 → 네이티브 앱 정리·기기 인수** 순서로 추적한다.

1차 정리·Next.js 업데이트·관리자 통계 최적화·지도 패널 분리와 내 제보 서버 페이지 조회를 운영에 반영했다. 관리자 조회 결과와 지도·검색·회원 조회의 의미를 보존하며 작은 PR로 검증했다. 합성 조회 횟수와 동일 설정의 초기 코드 크기는 비교했지만 실제 운영 DB의 성능 백분위·실기기 지도 표시 시간은 측정하지 않았다. 검증 중 발견한 계정 화면의 폭 전환과 모바일 알림의 제보 상세 연결도 보완했다.

## 검토 범위와 방법

웹·API·관리자·배치·문서·운영 체크포인트는 최신 `main`을 별도 작업 공간에서 확인했다. 기존 개발 폴더의 미커밋 변경은 보존했다. 모바일은 버전 0.1.53의 로컬 소스를 기준으로 검토한 뒤 사용자 승인에 따라 로컬 Git 복구 기준을 만들고 미사용 코드를 정리했다. 원격 앱 저장소·스토어 배포와 기기 인수는 아직 완료하지 않았다. 진행 중인 웹 게임도 검토에 포함하되 운영 기능으로 간주하지 않았다.

진입점·호출 참조·테스트·배포 및 운영 스크립트를 함께 확인했다. TypeScript import/export 분석은 삭제 후보를 찾는 보조 수단으로만 사용했다. 프레임워크 자동 진입점, 플랫폼별 파일, 테스트 전용 코드와 수동 복구 도구는 참조가 적다는 이유만으로 삭제하지 않았다.

| --- | --- | --- |

| 다국어·검색 노출 | 번역, 지역/상세 페이지, SEO, sitemap, IndexNow, 공유 링크 | 운영 진입점·캐시 갱신 도구 유지 |

모든 화면의 실사용 시나리오를 수동으로 다시 실행한 것은 아니다. 기존 로그인 상태의 회원 조회는 확인했지만, 새 소셜 로그인 완료·실제 데이터 쓰기·광고·iOS/Android 기기 성능·운영 DB 실행 계획은 후속 검증 범위다.

### 의존성 업데이트의 적용 범위

검토 시 웹의 Next.js는 16.3.4였다. [업데이트 PR #345](https://github.com/toilet-project/toilet-web/pull/345)를 1차 정리가 포함된 최신 기본 브랜치와 통합해 16.3.6으로 올렸다. 과거 설치 실패는 새 패키지 출시 후 대기 정책 때문이었다. 정책을 해제하지 않고 재검증해 전체 자동 검사·Workers 후보 빌드·상세 캐시 교차 배포 검사를 통과했다. 변경은 의존성 선언과 잠금 파일 두 개이며, 기존 프리뷰에서 실제 지도·검색·필터·상세·한국어/영어·지역 지도 확대와 회원의 제보/리뷰/좋아요/계정 조회를 확인했다. 병합 소스와 검증 산출물의 일치를 확인한 뒤 운영에 반영했다.

[Next.js 공식 보안 공지](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j)는 Node.js `ImageResponse`에서 공격자가 제어하는 SVG 입력을 처리하는 경로를 설명한다. 검토한 서비스 소스에는 `next/og`·`ImageResponse` 사용처가 없었다. 따라서 이번 정적 검토만으로 현재 서비스가 그 공격 경로에 노출됐다고 단정하지 않는다. 수정 버전은 이번 업데이트에 포함했다.

`undici`와 `brace-expansion`도 업데이트 후보다. 잠금 파일에서 전자는 Miniflare, 후자는 minimatch의 간접 의존성으로 확인했다. 빌드·미리보기 도구와 배포된 Worker에서의 실제 사용을 구분해 상위 패키지 업데이트를 검증해야 한다. Dependabot 경고에는 선언 파일·잠금 파일 및 여러 버전의 중복이 있으므로 경고 개수를 서로 다른 운영 취약점 수로 해석하지 않는다.

### 관리자 상세 분석

[관리자 PR #150](https://github.com/toilet-project/toilet-admin-api/pull/150)을 병합·운영 반영했다. 개요는 기본 집계만 조회하고 차원·유입 흐름·근거는 해당 탭을 열 때 조회한다. 기존 전체 응답을 유지하며 같은 조건의 조회 결과와 진행 중 요청을 재사용한다. 기간·필터 변경과 늦은 오류 응답을 보호하고 실시간 영역은 개요만 갱신한다.

합성 원본·비교 집계의 첫 개요 조회는 오늘 38→14회, 7일 36→12회였다. 모든 탭을 열면 필요한 전체 집계 비용은 남는다. 실제 운영의 완료 날짜 결과·다섯 탭·봇 포함/제외·필터를 변경 전과 비교했다. 전체 운영 DB 실행 계획·반복 성능 측정은 미실시다. [검증 범위](https://github.com/toilet-project/toilet-admin-api/blob/main/docs/service-analytics.md#화면별-상세-조회와-비용-검증)를 기준으로 해석한다.

### 웹 지도 화면과 내 제보

[지도 PR #360](https://github.com/toilet-project/toilet-web/pull/360)은 장소 검색 상태·취소를 별도 훅으로 분리하고 모바일 내비게이션과 계정 화면을 나눴다. 제보·내 제보·계정 패널은 열 때 불러오며 실패·재시도·로딩 중 닫기·회원 전환을 보호한다. 지도 SDK 생성·정리, 시설 선택·라우팅·상세 캐시는 기존 연결을 유지했다.

같은 운영 설정의 로컬 빌드에서 첫 화면의 고유 JavaScript 파일은 약 49.6KB 줄었다. 지도 주청크 감소율을 전체 초기 코드 감소율로 해석하지 않는다. 전체 자동 검사·프리뷰/운영 후보·캐시 교차 배포 검사와 실제 지도·검색·한국어/영어·시설 재선택·뒤로/앞으로·모바일 회원 조회를 확인했다. 실제 기기의 표시 시간·위치 권한 변경·회원 데이터 쓰기는 검증하지 않았다.

기존 데스크톱 계정 화면을 모바일 폭으로 전환할 때 빈 화면이 되는 문제를 발견해 [후속 PR #361](https://github.com/toilet-project/toilet-web/pull/361)에서 화면 크기 감지를 보완하고 프리뷰·운영에서 내 제보 조회 화면 유지와 모바일 전환을 확인했다. 최종 반영 상태는 [지도 WBS #359](https://github.com/toilet-project/toilet-web/issues/359)에서 확인한다. [상세 검증 문서](https://github.com/toilet-project/toilet-web/blob/main/docs/map-panels-optimization.md)에 범위·측정 한계를 남긴다.

### 내 제보 서버 페이지 조회

[API #235](https://github.com/toilet-project/toilet-api/pull/235)와 [웹 #365](https://github.com/toilet-project/toilet-web/pull/365)를 병합하고 API → 웹 순서로 운영 반영했다. 웹은 날짜·상태 조건의 본인 제보를 10개씩 조회하고 상태별 전체 건수를 유지한다. 최신 생성 시각과 ID로 정렬하며 시설명 조회도 반환 페이지로 제한한다. 알림 대상은 본인 상세 한 건을 먼저 펼쳐 보여주므로 오래된 제보에 도달하려고 중간 페이지를 모두 읽지 않는다.

추가 조회 실패 시 기존 목록을 보존하고 같은 페이지를 재시도한다. 중복 요청·ID와 필터/회원 전환의 늦은 응답을 막으며 세션 만료 시 목록·상세를 제거한다. 프리뷰에서 발견한 모바일 계정 전환의 제보 번호 누락을 함께 고쳤다. 본인·타인/비회원·없는 상세, KST 날짜 경계와 동일 시각 정렬을 실제 제한 JPQL 조회 및 HTTP 검사로 검증했다.

웹 전체 검사와 Workers·캐시 교차 배포 검사를 통과했다. API는 [Docker 사용 가능한 전체 이미지 빌드](https://github.com/toilet-project/toilet-api/actions/runs/37216328080)를 통과한 뒤 [계정 설정을 보존하는 운영 배포](https://github.com/toilet-project/toilet-api/actions/runs/37217037854)를 완료했다. 실제 로그인 상태의 프리뷰·운영에서 기간·상태 건수와 목록 순서, 더 보기, 오래된 상세 및 모바일 진입을 확인했다. 검증된 웹 산출물과 병합 소스의 일치, 최신 운영·직전 복귀 버전의 캐시 보호를 확인했다. 캐시 삭제·제보 저장·알림 읽음 처리·회원/시설 데이터 변경은 실행하지 않았다.

기존 모바일·구형 웹의 전체 배열 API는 유지한다. 모바일의 신규 조회 적용은 별도 작업이다. 건수 집계는 본인의 해당 기간 이력을 읽으며 offset 페이지 사이에 새 제보가 추가되면 경계가 이동할 수 있다. 반환량 제한이 실제 DB 성능 백분위 개선까지 입증하는 것은 아니다. [조회 계약·검증 한계](https://github.com/toilet-project/toilet-web/blob/main/docs/my-report-history-pagination.md)와 [WBS #363](https://github.com/toilet-project/toilet-web/issues/363)에서 추적한다.

### 모바일·공통 코드에서 보존할 부분

모바일 `src/map/api.ts`는 현재 로컬 카탈로그를 조회한다. 테스트 외 사용처가 없는 `areaCache.ts`의 `MapAreaCache`·`loadCachedMapArea`·`bufferedMapArea`와 미사용 바인딩 12곳만 정리했다. 실제 화면에서 사용하는 `areaCount`와 좌표 범위·마커 완전성 함수, 지도 집계의 중심점을 범위로 오해해 개수를 만들어내지 않는 보호는 유지했다. 미사용 검사를 기본 타입 검사에 추가하고 실제 지도 개수의 회귀 검증을 보완했다.

앱 소스·직접 작성한 네이티브 모듈을 로컬 Git으로 관리하고 테스트·타입 검사·Android/iOS 번들·Android ARM64 후보 빌드와 서명 검증을 통과했다. 에뮬레이터용 x86 후보의 카카오 지도 라이브러리 누락으로 종료되는 문제는 ARM64 후보로 교체했고 사용자가 앱 실행을 확인했다. 지원하지 않는 빌드를 차단하고 실제 APK 필수 라이브러리를 검사하도록 보완했다. 주요 흐름 전체·실제 휴대폰과 iOS 네이티브 빌드는 미검증이다. 후보에는 기존 로컬 소스에 이미 있던 오디오 기능도 포함되며, 오래된 APK와 비교하면 오디오 라이브러리의 `MODIFY_AUDIO_SETTINGS` 권한이 추가된다. 정리 자체는 권한·인증·광고·카탈로그 설정을 변경하지 않았다. [앱 검증·설치 후보의 제한](mobile-app-cleanup-verification-2026-10-05.md)을 기준으로 인수한다.

API·배치의 같은 계정 클래스들은 실제 보존·파기·복구 경로다. 중복을 줄이더라도 동시 배포가 필요한 변경으로 만들지 않도록 버전 계약과 동일성 검증부터 도입한다. 게임 아트 함수도 모바일에서 쓰이지 않는다는 이유만으로 지우면 웹 게임의 공유 원본과 어긋날 수 있다.

## 1차 삭제 후 실행 확인

웹 PR #357의 CI 프리뷰 산출물과 현재 PR의 소스·잠금 파일·환경 설정을 대조하고, 원격 업로드 없는 검사 및 로컬 Workers 실행을 확인했다. 비로그인 회원 진입과 정책·지역·시설 상세 URL은 정상 응답했다. 사용자 승인 후 같은 산출물을 [기존 웹 프리뷰](https://preview.geupddong.com/)에 반영했으며, 응답 버전이 검증 산출물과 일치하고 검색 제외·내비게이션 캐시 미저장 설정을 유지하는 것을 확인했다. 이전 프리뷰 버전은 복원 가능하게 보존했다.

| 프리뷰 브라우저 확인 | 결과 |
| --- | --- |
| 지도·검색·필터 | 실제 Kakao 지도 표시, 서울역 검색과 지도 이동, 24시간·CCTV 조건 적용 및 해제 후 목록 복귀 확인 |
| 시설 상세·화면 이동 | 지도 마커 선택, 주소·이용시간·편의시설·리뷰 조회, 뒤로/앞으로 이동 시 상세 진입 확인 |
| 지역 지도·다국어 | 상세의 지역 링크 진입, NAVER 지역 지도와 집계 마커 확대, 한국어↔영어 전환 및 선택 시설 유지 확인 |
| 회원 조회 | 기존 로그인 상태에서 내 제보·내 리뷰·내 좋아요·계정 관리·알림 표시 확인 |
| 모바일 화면 분기 | 작은 브라우저 화면에서 회원 진입 전환, 제보 조회, 장소 검색, 목록과 시설 상세 진입 확인; 실제 네이티브 기기 검증과 구분 |

확인한 흐름에서 정리로 인한 기능 문제와 브라우저 오류는 발견하지 못했다. 프리뷰는 실제 API·기존 회원 세션을 사용하므로 리뷰·좋아요·제보 저장, 알림 읽음 처리, 회원 정보 변경·탈퇴는 실행하지 않았다. 작은 화면의 캡처는 축소되어 시각 배치 검증의 근거로 사용하지 않았으며, 화면 구조와 상호작용만 확인했다. 전체 기능이나 데이터 쓰기까지 검증한 결과로 해석하지 않는다.

관리자 PR #148에서는 삭제한 클래스가 실행 JAR에 없는 것을 확인했다. 운영 DB와 분리한 H2 시험 환경에서 애플리케이션 기동과 시설/행정구역/좌표 페이지·지도 설정 응답을 확인했고, 기존 읽기 전용 화면에서 주소·좌표 조회를 확인했다. 이후 [운영 배포](https://github.com/toilet-project/toilet-admin-api/actions/runs/37200777522)가 정상 기동 검사를 통과했다. 실제 운영 관리자에서 시설 목록·상세 선택, 공공 시설 주소 검색, 지도 클릭에 따른 좌표·도로명 주소 역조회와 입력값 원상 복귀를 확인했으며 저장하지 않았다. 이는 전체 MySQL 통합 테스트 통과를 뜻하지 않는다.

웹은 PR 병합 결과와 검증 산출물의 소스 트리가 일치함을 대조한 후 운영에 반영했다. 운영 응답 버전 일치, 검색 노출 허용과 내비게이션 캐시 미저장 정책, 실제 지도·검색·필터·시설 상세·기존 회원의 제보/리뷰/좋아요/계정 조회를 확인했다. 브라우저 오류는 관찰되지 않았다. 운영·직전 복귀 버전의 캐시 등록과 정리 방지 로직을 확인했으며, R2 캐시 삭제·시설/회원 데이터 변경은 실행하지 않았다.
