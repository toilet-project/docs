# 현재 기능과 운영 상태

2026-09-17 · 개발 5주차 · 공개 제품 코드와 완료 WBS를 대조한 요약입니다. 실행별 세부 근거는 연결된 WBS에서 확인합니다.

## 사용자에게 제공하는 기능

- 카카오맵에서 현재 위치·장소를 기준으로 화장실을 찾고 상세 정보와 개방시간을 확인합니다.
- Google·Kakao 로그인 후 위치·운영 정보 제보와 처리 알림을 확인합니다.
- 모바일에서 위치 조건을 확인한 뒤 리뷰를 작성하고, 내 리뷰에서 조회·수정·작성자 연결 해제를 수행합니다.
- 내 리뷰·내 제보·알림은 공통 화면 안에서 기간 필터와 날짜 범위로 조회합니다.

리뷰는 **150m 이내·정확도 50m 이하·최근 5분 위치**를 서버에서 검사합니다. 같은 시설에는 작성 후 24시간이 지나야 다시 작성할 수 있고 수정·작성자 연결 해제는 작성 후 7일 이내입니다. 위치 검사는 조작 방지나 방문 사실을 완전히 보증하지 않습니다. [리뷰 계약·정책](../api/location-reviews.md)

## 운영자가 제공 품질을 관리하는 방식

| 문제 | 현재 처리 |
| --- | --- |
| 같은 이름이지만 서로 다른 시설 | 좌표·지역구 필터, 그룹 전체 순번 지도와 개별 정보 비교 |
| 실제로 중복인 시설 | 대표 지정 후 선택 항목만 숨김. 원본·리뷰·제보를 자동 병합하거나 삭제하지 않음 |
| 작업 목록에서만 제외하고 싶은 그룹 | 관리자별 작업 숨김. 사용자 공개 상태에는 영향 없음 |
| 확정 값과 다른 공공데이터 수신 | 변경 후보·수신 이력을 보관하고 반영/현재 값 유지/나중에 검토 |
| 숨긴 시설에 다시 변경 수신 | 숨긴 당시 근거와 비교. 반영해도 자동으로 공개하지 않음 |

## 완료와 혼동하지 않을 항목

- **자연 수신 관측:** 공공데이터의 실제 변경 수신과 확정 좌표 보존은 [10월 초 점검](https://github.com/toilet-project/docs/issues/95)에서 계속 확인합니다. 합성 변경 시험을 자연 수신 증거로 대체하지 않습니다.
- **사본 만료:** 보관 사본의 실제 만료·보호 기록 종료는 [별도 인수](https://github.com/toilet-project/docs/issues/94)입니다.
- **전체 서비스 자동 복구:** [후속 WBS](https://github.com/toilet-project/docs/issues/93)이며 현재 구현 완료로 소개하지 않습니다.
- **중복 작업 자동 재검토:** 현재 그룹 작업 숨김은 수동 설정입니다. “다른 시설로 확인 완료 → 변경 시 작업 목록 자동 복귀”는 미구현 제안입니다.
- **공개 리뷰 목록 UI:** 공개 API 구현과 모든 사용자 화면 구현을 동일하게 취급하지 않습니다. 이번 문서 정비로 새 UI를 추가하지 않습니다.
- **운영 쓰기 시험:** 중복 숨김의 쓰기·동시성·캐시 이벤트 시험은 시험 DB/CI에서 수행했고, 운영 시설을 임의로 숨겨 검증한 것은 아닙니다.

## 증거를 읽는 기준

CI 성공은 코드·시험 결과, 배포 성공은 실제 반영 결과, 사용자 인수는 해당 기기에서 확인한 결과입니다. 셋을 구분합니다. 캐시 최초 자동 정리는 안전 판정을 거쳤지만 후보가 없어 **삭제 0건**이었습니다. 전체 URL 생성 기록과 모든 URL의 동일 시점 fresh 보장 역시 구분합니다.
